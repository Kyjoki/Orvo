# Orvo

Личный веб-офис ИИ-агентов для подготовки требований, архитектурных предложений, кода, тест-кейсов и документации по материалам владельца. React/TypeScript, Next.js, eve, PostgreSQL и OpenAI API / Vercel AI Gateway. Основа интерфейса — предоставленный HTML-макет: изометрический офис, тёмная и светлая темы, список агентов и мобильная навигация.

Владелец сам создаёт и настраивает сотрудников внутри Orvo: их число и роли не заданы командой разработчиков. Создание владельца не добавляет сотрудников автоматически. Уже существующие профили и их данные сохраняются. Выполняются только запущенные задачи; командный сценарий использует до трёх выбранных сотрудников последовательно. [Двенадцать ролей команды разработки](docs/development-team.md) относятся к работе над репозиторием, а не к составу офиса в приложении.

## Локальный запуск без платных подключений

Требуется Node.js 24+ и npm. Команды выполняются из корня проекта:

```powershell
npm ci
npm run setup:test
npm run db:migrate
npm run owner:create
npm run dev
```

Откройте <http://127.0.0.1:3000>. Скрипт `setup:test` создаёт игнорируемые Git файлы `.env.local` со случайными секретами и `.orvo/test-access.json` с доступом владельца. Существующий `.env.local` не перезаписывается. Пароль не выводится в терминал: прочитайте локальный файл и войдите в закрытое пространство. Публичной регистрации нет. Не публикуйте эти файлы.

Это явно включённый `ORVO_TEST_MODE=1`: локальная PGlite в `.orvo/test-db/`, тестовое хранение вложений в `.orvo/test-files/` и детерминированный поставщик вместо облачной модели. PGlite работает в изолированном Node-процессе с IPC; рабочая PostgreSQL от этого механизма не зависит. В настройках выберите тестового поставщика, модель `test/deterministic`, сохраните и проверьте соединение. Тестовые результаты помечены; их токены синтетические. Настоящие ключи и внешние сервисы для этого режима не нужны.

После входа настройте профиль и часовой пояс, создайте нужного сотрудника и затем первую задачу. [Демонстрационный сценарий](docs/demo.md) показывает память, подтверждение и сохранённый результат.

## Подключение рабочей модели

Создайте приватный `.env.local` по `.env.example` или задайте переменные в окружении сервера. Нужны `DATABASE_URL` PostgreSQL, `BETTER_AUTH_URL`, независимые случайные `BETTER_AUTH_SECRET` и `ORVO_RUNTIME_SECRET` длиной не менее 32 символов, `ORVO_RUNTIME_URL`, `OPENAI_API_KEY` для OpenAI либо `AI_GATEWAY_API_KEY` для Gateway; тестовый режим должен быть отключён. Для вложений подключите закрытый S3-совместимый bucket. Полный список переменных и особенности размещения — в [инструкции эксплуатации](docs/operations.md).

Выполните миграции и однократное создание владельца. Чтобы пароль не попадал в историю PowerShell, передайте его через окружение процесса из скрытого ввода:

```powershell
$env:ORVO_OWNER_EMAIL = Read-Host 'Email владельца'
$env:ORVO_OWNER_NAME = Read-Host 'Имя владельца'
$orvoPassword = Read-Host 'Пароль (не менее 12 символов)' -AsSecureString
$orvoPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($orvoPassword)
try {
  $env:ORVO_OWNER_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($orvoPointer)
  npm run owner:create
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($orvoPointer)
  Remove-Item Env:ORVO_OWNER_PASSWORD -ErrorAction SilentlyContinue
  $orvoPassword.Dispose()
}
```

В настройках выберите OpenAI API или Vercel AI Gateway, укажите доступную текстовую модель и нажмите проверку подключения. Она делает ограниченный запрос и может расходовать токены. Наличие названия модели в профиле не подтверждает доступность. Ключи используются только сервером; в профилях агентов их нет.

В настройках офиса и профиле сотрудника есть список семи моделей из доступного в этой среде Codex: GPT-6.1 Sol, GPT-6 Astra, GPT-6 Sol, GPT-6 Luna, GPT-5.6 Sol, GPT-5.6 Terra и GPT-5.6 Luna. Это сохранённые варианты выбора на 19 октября 2026, не автоматическое получение моделей аккаунта ChatGPT. Для OpenAI API используются обычные model-id, для Gateway — `openai/<model-id>`. Поддержку и доступ проверяет сервер через каталог выбранного провайдера и отдельный запрос. Сохраняются ручной ввод других моделей и наследование общей модели агентом. Выбор в списке не вызывает модель. При тестовом провайдере эти варианты недоступны для нового выбора. Вход через аккаунт ChatGPT этим изменением не реализован.

## Реализованные возможности и границы

| Возможность | Реализация |
| --- | --- |
| Сотрудники офиса | Владелец создаёт произвольные профили, задаёт роли и инструкции, редактирует и архивирует их; исторические профили сохраняются |
| Офис и панели | Три зоны, офис/список, панель и шесть вкладок каждого агента, темы, мобильный режим |
| Задачи | Серверные состояния, лимиты, отдельная сессия eve, этапы, пауза/отмена на границах, принятие и до трёх циклов правок |
| Память | Записи агента, проекта и пространства; версии инструкций, редактирование, отключение записей; это данные приложения, без fine-tuning |
| Чат | Сохранённые сообщения в общем и задачно ориентированном контексте; обычный чат самостоятельно не запускает ответ модели |
| Подтверждение | Одноразовая публикация конкретного правила в общей памяти; сервер проверяет версию, параметры, срок и права |
| Результаты | Сохранённый текст/Markdown, версии, просмотр, копирование и скачивание; генераторов DOCX/XLSX/PDF нет |
| Вложения | TXT/Markdown и PDF с текстом; до трёх файлов задачи по 10 МБ, извлечённый текст до 50 000 символов; OCR отсутствует |
| Синхронизация | Серверный snapshot с polling и backoff; сохранённый inbox, журнал событий и токены |
| Стоимость | Неизвестная цена показана как недоступная; сервер не подставляет фиктивные нулевые расходы |
| Внешние действия | GitHub, почта, браузер, shell, календарь и Ritm не подключены. Роли готовят материалы и предложения |

Прямой OpenAI Responses API проверен на реальных запросах GPT-6 Luna; результаты описаны в [отчёте живого прогона](docs/live-test-report.md). Вызовы через Gateway и живое S3 пока не проверены. Локальные тесты используют явный тестовый режим. Облачное размещение не подтверждено. Для 429/5xx runtime выполняет до трёх попыток этапа с durable backoff и разбором `Retry-After` (задержка ограничена 1–30 секундами). Неоднозначно завершённый вызов без подтверждённой повторяемой ошибки автоматически не дублируется: сохраняется резерв бюджета, требуется осознанный повтор. На постоянно работающем Node-хосте Next instrumentation повторяет доставку outbox каждые 10 секунд; для serverless нужен отдельный надёжный механизм пробуждения.

## Проверки и структура

```powershell
npm run typecheck
npm test
npm run build
```

До изменения состава сотрудников были подтверждены 26/26 тестов, сборки eve и Next production, семь HTTP runtime-сценариев, локальное продолжение после перезапуска и девять проверок файлов. Тогда в браузере открывали 12 панелей и чатов тестовых профилей, проверяли обе темы на шести ширинах, сохранение данных и путь создания/принятия результата. Эти исторические результаты не подтверждают новую схему создания сотрудников и не задают их обязательное число. Актуальный журнал — [docs/progress.md](docs/progress.md). Все генерации в тех проверках использовали явный тестовый провайдер; качество облачной модели не проверялось.

Добавлен GitHub Actions workflow: Node.js 24, `npm ci`, typecheck, тесты и сборка без ключей модели и платных вызовов. Наличие workflow не означает подтверждённый запуск CI на GitHub. Остались три moderate предупреждения зависимостей в цепочке eve/just-bash/sprintf; shell-инструменты приложения отключены, предупреждения требуют дальнейшего обновления зависимостей.
