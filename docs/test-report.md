## Серверные сценарии

`scripts/office-smoke.ts`: финальный прогон `0384fe14`, 9 проверок PASS, exit 0. Семь функциональных сценариев и две проверки сохранности/завершения:

1. Задача → один тестовый артефакт → принятие до completed.
2. Повтор создания с тем же requestId → тот же ID, одна запись.
3. waiting_for_input → ответ → продолжение с тем же runtime ID.
4. Пауза отложенного задания → продолжение → completed. Пауза уже выполняющегося платного запроса этим сценарием не проверялась.
5. Отмена до исполнения → cancelled без записи использования модели.
6. Управляемая ошибка 429 → ограниченный повтор → результат; две попытки.
7. Одобрение памяти создаёт ровно одну запись; тот же requestId возвращает сохранённый ответ. Новый requestId отклонён с HTTP 409, количество записей осталось один. Некорректное сообщение этого отказа описано ниже.
8. Сравниваемые настройки профиля Пикселя и полный снимок его основного задания совпали со значениями до теста. Проверка профиля включает имя, роль, описание, аватар, инструкции/версию, модель, права, лимиты, архивный флаг и версию профиля; не является сравнением всех полей профиля.
9. Активных заданий финального прогона не осталось. Созданное тестовое правило мягко удалено; число активных записей памяти вернулось к исходным трём.

Первый прогон обнаружил несовпадение ожидаемого кода повторного approval (`APPROVAL_CONFLICT`) с фактическим (`RUNTIME_INPUT_NOT_READY`). Финальный тест проверяет реальный контракт одноразовости отдельно от текста ошибки; это уточнение теста, а не исправление приложения. Сохранились помеченные завершённые/отменённые задачи и история. Оставшаяся ready_for_review задача первого прогона также принята после проверки.
