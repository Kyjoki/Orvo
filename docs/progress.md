# Прогресс Orvo

Дата записи: 19 октября 2026, Asia/Qyzylorda.

## Контекст продолжения

Источник требований — `Orvo_Codex_Prompt.txt`; визуальный эталон — `Orvo-Pixel-Office-Seated.html`, предоставленные владельцем. Интерфейс переносится в компоненты приложения. Встроенного iframe с девятью экранами прототипа нет. Материалы Threat Hunting в рабочей папке не относятся к заданию, их следует сохранять.

Принятый стек: Next.js/React/TypeScript, Node 24+, Better Auth без публичной регистрации, PostgreSQL, eve через `withEve`, Gateway, закрытый S3. PGlite и тестовая генерация доступны только в явном локальном тестовом режиме. Одно приложение/Workflow. Владелец сам определяет число и роли сотрудников Orvo; создание владельца не должно добавлять их автоматически. Существующие профили и данные сохраняются.

## Области ответственности текущей работы

| Исполнитель | Область | Критерий готовности |
| --- | --- | --- |
| Координатор | Интеграция, решения, миграции и итоговая проверка | Согласованная сборка и подтверждённые результаты без ложных обещаний |
| Frontend-разработчик | `src/components/`, CSS и визуальные состояния | Интерфейс по макету, маршруты и панели, мобильная версия, реальные серверные данные |
| Инженер runtime | `agent/`, runtime/API взаимодействие по согласованию | Durable ограниченный запуск, ожидания/управление, честное разделение test/Gateway |
| Технический писатель | `README.md`, `docs/*.md`, `.github/workflows/ci.yml` | Инструкции по реальному коду, архитектура, демонстрация, ограничения, восстановление и CI без секретов |

Это историческое распределение исполнителей конкретного этапа работы по репозиторию. Текущий [регламент команды разработки](development-team.md) задаёт двенадцать специализаций; среда поддерживает настоящих субагентов и до четырёх одновременных активных слотов, включая координатора. Роли подключаются по задаче, а не объявляются все фактически созданными. Сотрудники внутри Orvo создаются и настраиваются владельцем независимо от этого регламента.

## Что имеется в коде

Владелец/сессия, SQL-миграции, настраиваемые сотрудники, права и версии, изолированная память, сохранённый чат, задачи и управляющие команды, сессии eve/Workflow, командные этапы, квоты/резервы, запрос общей памяти, артефакты Markdown, вложения и inbox. Старый набор из 12 шаблонов остаётся только явным fixture тестового режима; в рабочем пространстве автоматическое создание набора запрещено. Подробные ограничения перечислены в README и архитектуре.

## Следующие проверки и ограничения

Локальные тесты и сборка завершены. На постоянном Node-хосте pending outbox доставляет серверный dispatcher независимо от браузера; для serverless нужен scheduler. Локальное продолжение проверено с тем же build/runtime, но инфраструктура production PostgreSQL/Workflow/S3 и облачное восстановление не проверялись. Общий чат сохраняет сообщения без модельного ответа; OCR и внешние инструменты не реализованы. Подключение живых ресурсов выполняется только в пределах полномочий владельца. Исходник интерфейса — пользовательский HTML-макет; приложение использует собственные компоненты и серверную модель данных.

## Последние изменения

- Runtime получил до трёх попыток этапа для 429/5xx, durable backoff и разбор `Retry-After`; задержка ограничена 1–30 секундами. Неизвестные исходы без подтверждённой повторяемой ошибки автоматически не дублируются.
- Тестовая PGlite вынесена в отдельный Node IPC-процесс `scripts/embedded-db.mjs`; PostgreSQL production работает прежним путём. CLI ожидают закрытия БД перед завершением.
- В `src/instrumentation.ts` добавлен dispatcher раз в 10 секунд, вызывающий защищённый POST `/api/runtime/drain`. Он повторяет доставку pending outbox без браузера; serverless требует отдельного scheduler.
- Исправлено пространство имён XML в SVG-источнике иконок; визуальные проверки выполнены после исправления.
- По отдельному ревью исправлены четыре проблемы: приватный sealed S3-объект после загрузки, whitelist доменных ошибок, потоковый предел JSON и SQL leases outbox с heartbeat. Это исправления реализации, не подтверждение живого S3.
- Общее правило статуса агента отдаёт приоритет running/waiting перед старой ready_for_review; добавлена регрессия.
- Подтверждён факт eve 0.80.1: локальный world использует `.eve/.workflow-data` несмотря на переопределение окружением. Не утверждать изоляцию dev/production world; нужны отдельные рабочие директории/тома и остановка конкурирующего процесса.
- Старый локальный `app` после повреждения, связанного с прежним принудительным выходом CLI, сохранён. Текущее игнорируемое `.env.local` выбирает новый `app-verified`; секреты и значения доступа сюда не переносятся.
- Добавлена конфигурация GitHub Actions на Node.js 24: install/typecheck/test/build без модельных ключей и платных запросов. Запуск на GitHub ещё не подтверждён.
- Аудит оставляет три moderate предупреждения в зависимостях eve/just-bash/sprintf; shell-инструменты отключены. Полный production риск требует повторного аудита и обновления зависимостей.
