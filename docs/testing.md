# Проверка Orvo перед публикацией

## Как проходить

Используйте отдельные задания с префиксом `[ПРОВЕРКА]`. Не меняйте основной бриф владельца. В локальном тестовом режиме ответы помечены «ТЕСТОВЫЕ ДАННЫЕ» и не подтверждают качество настоящей модели. В обычном режиме запуск задачи может расходовать токены.

Для каждого шага записывайте: дату, окружение, ожидаемый и фактический результат, ID задачи и снимок ошибки. Актуальные результаты: [test-report.md](test-report.md).

## 1. Локальная проверка

| № | Действия | Что должно получиться |
|---|---|---|
| 1 | Открыть офис, затем «Агенты». Обновить страницу. | Пиксель виден один раз; архивные сотрудники не появляются в офисе. Комната доступна в режиме «Офис». |
| 2 | Нажать Пикселя. По очереди открыть обзор, чат, память, инструкции, инструменты и активность. | Все шесть разделов доступны и относятся к одному сотруднику. Ненастроенные внешние инструменты отмечены явно. |
| 3 | Сохранить помеченное сообщение в общем чате. Обновить страницу и открыть чат снова. | Сообщение осталось, дубликатов нет. Общий чат сам не запускает модель и не создаёт задачу. |
| 4 | Создать задачу: «Предложи концепцию лендинга студии керамики: секции, палитра HEX, шрифты и мобильная версия». Проверить данные перед запуском. | Создана одна задача с выбранным исполнителем и лимитами. В тестовом режиме результат явно помечен как тестовый. |
| 5 | Открыть материал задачи, скачать его и принять результат. | Текст доступен владельцу; задача становится «Завершено», материал — «Принято». |
| 6 | На отдельной задаче запросить правки с конкретным комментарием. | Создана следующая версия, предыдущий материал доступен; комментарий не потерян. |
| 7 | Запустить отдельную задачу с запросом уточнения. Дождаться «Нужен ответ», обновить страницу, ответить и продолжить. | До ответа нет результата и расхода на генерацию; после ответа продолжается та же задача. |
| 8 | На отдельной задаче нажать паузу, дождаться подтверждённой паузы, затем продолжить. Ещё одну задачу отменить до запуска. | На паузе новые этапы не запускаются; отменённая задача не создаёт результат. Уже начатый вызов может закончиться до применения паузы. |
| 9 | Проверить подтверждение записи в общую память: одобрить один раз, затем повторить тот же запрос. Отдельное предложение отклонить. | Одно одобрение создаёт одну запись; повтор не создаёт дубликат. Отклонение ничего не публикует. |
| 10 | Приложить TXT, Markdown и PDF с текстом. Проверить ложный PDF и файл больше 10 МиБ. Открыть приватную ссылку без входа. | Допустимый текст извлечён; неверные/слишком большие файлы отклонены; без входа материал недоступен. PDF без текстового слоя требует отдельной проверки: OCR не реализован. |
| 11 | В изолированном окружении повторить запрос создания с тем же requestId, вызвать 429, проверить бюджет и запрет инструмента. | Повтор не дублирует задачу; временная ошибка даёт ограниченный повтор; лимиты и права проверяет сервер. Не отправляйте искусственные ошибки настоящему платному провайдеру. |
| 12 | На телефоне открыть офис, список, панель, задачу и чат; проверить прокрутку и кнопки. | Страница помещается по ширине, нижняя навигация и формы доступны. В мобильном офисе список включается по умолчанию. |
| 13 | На достаточно долгом реальном выполнении открыть офис. Проверить ожидание, работу, паузу и завершение; отдельно системную настройку уменьшения движения. | Движение персонажа только при серверном running; при ожидании/паузе/завершении он статичен. Уменьшение движения отключает анимацию. Короткий тестовый ответ может завершиться между опросами. |
| 14 | В тестовом окружении остановить сервер во время ожидания, затем запустить тот же build. Отдельно прервать сеть браузера и восстановить её. | Нет ложного статуса подключения; сохранённая задача и история возвращаются. Продолжение не дублирует вызов/артефакт. Локальная проверка не подтверждает восстановление облачной инфраструктуры. |

## 2. Команды автоматической проверки

Нужен Node.js 24 или новее. Из корня проекта:

```powershell
npm run typecheck
npm test
npm run build
```

Для уже запущенного локального тестового офиса с `.orvo/test-access.json` (во время прогона не переключайте provider/model и не запускайте другой runtime-тест):

```powershell
npx tsx scripts/office-smoke.ts
npx tsx scripts/files-smoke.ts
```

Проверки создают помеченные тестовые задания/материалы. `office-smoke.ts` требует тестовый провайдер и не меняет настройки, состав сотрудников или старые задачи. Секреты и cookie нельзя включать в отчёт. Старый `runtime-smoke.ts` рассчитан на исторический набор из двенадцати fixtures и меняет данные; для текущего офиса используйте `office-smoke.ts`.

## 3. Перед закрытым Vercel Preview

- Подключить настоящую модель с небольшим лимитом и проверить содержательный дизайн по шагу 4: соответствие брифу, конкретные цвета/типографика, мобильная версия, отсутствие выдуманных действий.
- Проверить долгий вызов и анимацию, отказ провайдера, реальный учёт токенов и отсутствие ключей в браузере/логах.
- Подготовить production PostgreSQL, приватное хранилище, durable runtime и доставку фоновых задач без открытой вкладки. Локальная PGlite не является production-хранилищем.
- На самом Preview повторить вход, задача → материал → принятие, ожидание → продолжение, файлы, переподключение и перезапуск. Отдельно проверить восстановление резервной копии.
- После успешной закрытой проверки принимать решение о публичной публикации.

Сейчас интерфейс и локальный тестовый runtime не подтверждают готовность настоящей модели или облачного размещения. Общий чат сохраняет сообщения; внешние GitHub/браузер/код/почта/Ritm не подключены.
