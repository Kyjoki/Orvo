# Безопасность Orvo

Документ описывает текущую защиту и границы подтверждённых проверок. Preview имеет статус `READY`; прошли 16 живых HTTP-проверок, пять проверок Blob SDK, загрузка через UI без CSP-ошибок и одна реальная задача до принятого результата. Это не сертификат безопасности и не проверка всех сбоев. Подробности — в [progress.md](progress.md); секреты и email владельца здесь не публикуются.

## Вход и разделение окружений

Better Auth обслуживает одного владельца, публичная регистрация отключена. Владелец создаётся административным скриптом с паролем от 12 символов; открытого initial-setup endpoint нет. Cookie сессии использует HttpOnly библиотеки и Secure на HTTPS/production; срок сессии — семь суток, обновление — раз в сутки.

Приложение проверяет не только наличие сессии, но и совпадение пользователя с владельцем пространства. Изменяющие пользовательские API требуют точного `Origin`. В Vercel Preview auth и CSRF используют неизменяемый `https://VERCEL_URL`, без wildcard доверия ко всем preview-hosts. Локальный тестовый режим отклоняется на Vercel и на внешнем origin.

Служебный eve/RPC имеет отдельный bearer `ORVO_RUNTIME_SECRET`, сравниваемый с постоянным временем для одинаковой длины. Browser cookie его не заменяет. При обращении к текущему защищённому Vercel deployment добавляется trusted OIDC header; это front-door проверка платформы поверх собственных прав Orvo. Секретный bypass fallback применяется только к тому же deployment origin. Перенаправление служебного запроса не разрешено.

## Лимиты по фактическому коду

Счётчики хранятся в SQL `rate_buckets`; идентификатор bucket — HMAC от области и IP/email/владельца с серверным секретом. Перезапуск экземпляра не обнуляет их. На Vercel IP берётся из проверяемого формата `x-vercel-forwarded-for`; вне Vercel используется общий `local-client`, а не произвольный клиентский forwarded header.

| Операция / область | Предел |
| --- | --- |
| POST auth по IP | 60 за 60 секунд |
| Вход email по IP | 10 за 15 минут |
| Вход по нормализованному email | 12 за 15 минут |
| Дополнительный limiter Better Auth | 30 за 60 секунд, хранение в БД |
| Snapshot состояния по владельцу | 180 за 60 секунд |
| Команды по владельцу | 120 за 60 секунд |
| Запись/завершение файла по владельцу | 60 за 60 секунд |
| Скачивание файла по владельцу | 120 за 60 секунд |
| Проверка модели | До 5 за час на пространство; нетестовый запрос резервирует 512 токенов |

Это фиксированные окна, а не гарантия защиты от всех DoS. При превышении custom SQL limiter возвращает 429 с `Retry-After`; при недоступности его БД — 503, а не неограниченный пропуск. Auth-wrapper нормализует ответ Better Auth 429: если стандартный `Retry-After` отсутствует, берёт числовой `X-Retry-After`, иначе использует 60 секунд. Интерфейс входа показывает время ожидания. Проверки выполняются дополнительно к сессии и правам.

JSON читается с потоковым пределом: команда 80 000 байт, file registration/completion 16 384 байт, все auth POST 16 384 байт, служебный domain RPC 150 000 байт. Ограниченный auth POST заново формируется перед передачей Better Auth. Схемы проверяют параметры и разрешённые операции. Объём выдаваемого snapshot ограничен текущими запросами домена; это не интерфейс для неограниченной выгрузки всей истории.

Токены и шаги резервируются атомарно перед модельным вызовом. Стартовые значения пространства: 200 000 токенов, 24 000 на задачу, 3 000 в ответе, до 10 шагов и 2 одновременных задач. Владелец может менять разрешённые настройки; фактический предел шага — минимум ограничений задачи, сотрудника и пространства. Командный план ограничен тремя последовательными сотрудниками, правки — тремя циклами. Для 429/5xx допускаются три попытки этапа с durable backoff 1–30 секунд; неизвестный исход автоматически не дублируется. Бюджет приложения не является гарантией окончательного счёта провайдера.

## Файлы и результаты

На Vercel используется private Blob; постоянный read/write token остаётся серверным. Браузер получает разрешение только на staging PUT: конкретный pathname, Content-Type, предельный размер, срок до 15 минут, без overwrite. Сервер повторно проверяет принадлежность файла, фактический размер, UTF-8/формат PDF и извлечённый текст.

До трёх вложений задачи, по 10 MiB; до 500 активных файлов пространства; извлечённый текст до 50 000 символов. Квота 500 считается атомарно под блокировкой workspace: учитываются `ready` и ещё не истёкшие `uploading`, а не все исторические записи. Для PDF проверяется сигнатура, затем извлечение текста; OCR отсутствует. Шаблонный фильтр отклоняет узнаваемые ключи и присваивания секретов, но не гарантирует обнаружение всех чувствительных данных. Владелец должен исключать секреты из материалов.

При новой регистрации ограниченная уборка обрабатывает обычно три, максимум пять устаревших staging-объектов. Она использует lease, проверяет точный staging-key, сохраняет метаданные и не удаляет `ready`/sealed. Это уборка по обращению, без гарантии очистки idle Preview отдельным таймером.

Проверенные байты сохраняются в отдельный приватный `sealed` объект, который не доступен через исходное PUT-разрешение. Конкурентное завершение проверяет сохранённое состояние; Blob-повтор принимает существующий sealed объект только при совпадении SHA-256. Скачивание идёт через потоковый API с проверкой владельца, `private, no-store`, `nosniff` и Content-Disposition. Публичные постоянные URL чтения не выдаются. S3 вне Vercel имеет аналогичный путь закрепления байтов; живое S3 не заявляется проверенным.

Артефакты отображаются как текст, полученный код/HTML не исполняется. Материалы документов и ответы модели — недоверенные данные: память и инструкции не расширяют серверные права. Общий чат сохраняет сообщения без скрытого запуска автономной работы. Память — данные приложения, без fine-tuning; отключение записи не удаляет ранее отправленный провайдеру контекст.

## CSP и заголовки

`src/proxy.ts` создаёт случайный nonce для каждого HTML-запроса на пользовательских маршрутах и заменяет клиентские nonce/policy headers. CSP ограничивает script с nonce и `strict-dynamic`, запрещает встраивание страницы, object/frame и смену base, оставляет формы на своём origin. Для React style attributes разрешён `style-src 'unsafe-inline'`; в development дополнительно разрешены eval и локальные WebSocket. Это осознанные исключения, CSP не называется полной изоляцией.

Next добавляет `nosniff`, `DENY`, `no-referrer`, ограничения Permissions-Policy, same-origin COOP/CORP и отключение DNS prefetch. На Vercel добавлен HSTS. `connect-src` разрешает свой origin и точные пути/домены Blob из политики; альтернативный прямой S3-upload потребует отдельного согласованного allowlist его origin, не отключения CSP целиком.

## WAF и зависимости

Для Preview активно опубликовано бесплатное deny-правило по точным путям `/.env`, `/.env.local`, `/.git/config`, `/wp-login.php`, `/xmlrpc.php`, `/phpmyadmin`. Оно не распространяется на другие окружения или произвольные похожие пути. В браузере с Vercel SSO проверен 403 на `/.env` с текстом «This request was blocked». Raw-запрос без Vercel-аутентификации может раньше получить 302 на login; это другой слой защиты, не доказательство неисправного WAF. Basic System Rules активны. OWASP managed ruleset требует платного изменения плана и не подключён.

Аудит показывает три moderate предупреждения в цепочке eve/just-bash/sprintf, advisory `GHSA-hp3w-g68c-fv3c`, без high/critical. Доступного исправления без major downgrade сейчас нет. Shell-инструменты приложения отключены; это снижает доступность соответствующего пути, но не удаляет advisory из зависимостей.

## Что остаётся проверить

Первоначальные HTTP-проверки подтвердили вход, cookies, auth/private Blob и CSP/заголовки; отдельно прошли загрузка через UI, реальный Workflow и WAF 403. Последующее усиление включает обязательную MFA с grant на сессию, private Queue consumer, независимый reconciler, зашифрованные копии и атомарный restore с карантином. Прошли 71/71 тест, настоящий запуск без вкладки, scratch restore и откат при ошибке. Доказательства и оставшиеся границы — в [hardening-test-report.md](hardening-test-report.md). Реальный TOTP подключает владелец; Production требует отдельной настройки.

GitHub, shell, почта, браузер и произвольное исполнение кода отключены; генерация предложения не меняет репозиторий и не публикует его. Секреты размещены только серверно, `.vercelignore` пропускает исходники по allowlist. Это не заменяет проверку build output, зависимостей, backups и прав облачных ресурсов. Первый ошибочно назначенный Production deployment удалён; действующий Production не оставлен, отдельные Production-ресурсы не подготовлены. Подробная история — в [vercel-deployment.md](vercel-deployment.md).
