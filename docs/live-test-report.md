## Код и проверки

- Добавлены прямой Responses API клиент (`store:false`, фиксированный адрес, deadline, внешний abort, проверка completed и usage) и ветка OpenAI в исполнении задач.
- Сервер различает OPENAI_API_KEY и AI_GATEWAY_API_KEY. Смена провайдера снимает прежнее подтверждение модели.
- Прошли **34/34** теста, включая 5 мок-проверок OpenAI и разделение credentials между провайдерами; TypeScript, сборки eve и Next прошли.
- Отдельный ревьюер проверил код, очистку/границы тестов и обращения с ключом; живые вызовы выполнял координатор.

## Ограничения

- Orvo пока работает локально с PGlite и тестовым файловым хранилищем. Vercel, production PostgreSQL/S3, резервные копии и облачное восстановление этим прогоном не проверены.
- `ORVO_TEST_MODE=1` нужен для локальных адаптеров. Старые метаданные `test` у usage/артефакта определяются этим окружением и могут быть true даже для живого OpenAI вызова. Подлинность этого прогона подтверждается прямыми запросами, завершёнными ответами и usage, не этим флагом. Требуется разделить признак локального окружения и fixture-провайдера в метаданных.
- Из прежнего прогона остаётся неточное сообщение повторного approval с новым requestId. Полный цикл правок, живые ошибки провайдера, отключение сети и рестарт выполняющегося OpenAI запроса ещё не проверены.
- Результаты являются текстовыми концепциями. Генерация визуального макета, изменение репозитория, запуск кода и публикация сайта инструментами Пикселя не выполняются.
